## C-01 — a project-local copy for the 131 confirmed photos that only exist in the Syncthing folder

- Exact list: `docs/audit/2026-10-20/c01_copy_plan_2026-10-22.json` (id, status, species, src, dest, sha256, bytes).
- 131 rows (104 approved + 27 manually_verified), 321.8 MB, 84 species folders under `photos/confirmed_plants/`. No destination exists yet; no two copies share a name; every source file exists and its sha256 equals the row's `file_hash`.
- Examples:
  - 8197 *Tubaria furfuracea* `PXL_20260208_111748642.jpg` → `confirmed_plants/tubaria-furfuracea/PXL_20260208_111748642.jpg`
  - 16003 *Sonchus oleraceus* `PXL_20260602_130728348.jpg` → `confirmed_plants/sonchus-oleraceus/PXL_20260602_130728348.jpg`
- **How (recommended):**
  1. `shutil.copy2` each src → dest. A copy, never a move or a delete. 30 GB free.
  2. Check the copy's sha256 against `file_hash`. On a mismatch, delete that partial copy and leave the row untouched.
  3. Set `confirmed_copy_path = dest` with an `observation_edits` row (old NULL → dest, `edited_by='audit:C-01'`).
  4. Read back every row by id and check the file exists.
  - `file_path` is not changed: it stays the origin in the Syncthing folder.
- **Why not move `file_path` to the copy?**
  - The Syncthing scanner matches already-ingested files by path first (`syncthing.py:252–262`). Moved rows would fall to its sha256 tier.
  - They would still be skipped (no re-import), but 322 MB would be hashed on every scan pass, every 60 s (`syncthing.py:514`).
  - With `confirmed_copy_path` the copy exists (the data-loss risk is gone) at no scan cost. Display still reads `file_path`, so if the phone ever deleted an original, that photo would need repointing to its copy.
- **Alternative (B):** copy into `photos/pipeline2/` and point `file_path` at the copy (the copy-on-ingest convention). It costs the hashing above, unless the scanner is changed.
