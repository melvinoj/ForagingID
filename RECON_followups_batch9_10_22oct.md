## C-01: why the dry run recommends `confirmed_copy_path`, not a `file_path` move

- The Syncthing scanner decides "already ingested" first by path (`syncthing.py:252–262`), then by sha256 (`:266–290`).
- If the 131 `file_path`s moved into `photos/pipeline2/`, their originals would no longer match by path. They would still be skipped, because the hashes match, so there would be no re-import. But the scan loop runs **every 60 s** (`syncthing.py:514`) and would hash those 322 MB every minute.
- `confirmed_copy_path` is what approve writes today (`copy_single`, `photos/confirmed_plants/<species>/`), and 2,116 rows already use it. It ends the "only copy" risk, keeps the origin in `file_path`, and costs the scanner nothing.
- Display still reads `file_path`. If a phone-side delete ever removed an original, its photo would be shown from nowhere until repointed — but the copy would exist.
